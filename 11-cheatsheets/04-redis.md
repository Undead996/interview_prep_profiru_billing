# Redis и Memcached: шпаргалка

## Сравнение (по памяти)

| | Memcached | Redis |
|---|---|---|
| Данные | только KV | строки, hash, list, set, zset, stream, bitmap |
| Атомарность | `incr/decr`, `cas` | `INCR`, `SETNX`, `MULTI/EXEC`, **Lua** |
| TTL | на ключ | на ключ |
| Персистентность | ❌ | ✅ RDB/AOF |
| Репликация/failover | ❌ | ✅ реплики, Sentinel, Cluster |
| Структуры для очередей/локов | ❌ | ✅ |
| Типичная роль | кэш ответов/справочников | кэш + структуры + локи + счётчики |

## Что можно и нельзя кэшировать

```
✅ справочники, цены (с версией), дорогие чистые вычисления, курсы (TTL)
⚠️ отображаемый баланс (не источник решения), агрегаты (с версией/as-of)
❌ решение о списании, проверка лимита, факт существования платежа, суммы для отчётности
```
**Правило:** если на данных принимается решение о деньгах — это не кэш.

## Cache-aside

```php
$key = "catalog:v3:service:{$code}";       // ← версия в ключе
$cached = $cache->get($key);
if ($cached !== null) return ServiceConfig::fromArray($cached);
$config = $db->byCode($code);              // источник правды
$cache->set($key, $config->toArray(), 300);
return $config;
```

Инвалидация: TTL + явный `DEL` + **версия в ключе** (+ событие при многих инстансах).
Никогда `KEYS *` на проде — только `SCAN` маленькими батчами.

## Лок: `SET NX PX` + release по токену

```php
// захват — одной атомарной командой (не SETNX + EXPIRE!)
$redis->set("lock:{$res}", $token, ['nx', 'px' => $ttlMs]);

// освобождение — только своим токеном, атомарно через Lua
$lua = "if redis.call('get', KEYS[1]) == ARGV[1] then return redis.call('del', KEYS[1]) else return 0 end";
$redis->eval($lua, ["lock:{$res}", $token], 1);
```
**Правила:** TTL обязателен (иначе вечный лок) · освобождать только своё · лок — **оптимизация**,
а не гарантия корректности. Гарантия «ровно один раз» — `UNIQUE` в БД.

## Идемпотентность: где хранить

| | Redis | БД |
|---|---|---|
| Скорость | очень быстро | быстро (одно дерево) |
| Гарантия при сбое | ❌ теряется при сбросе/падении | ✅ есть |
| История | ❌ TTL всё забывает | ✅ можно посмотреть |

→ **Гарантия в БД** (`UNIQUE(idempotency_key)`, `processed_event`), Redis — только быстрый фильтр.

## Rate limit (с оговорками)

```php
$key = "rl:pay:{$userId}:" . floor(time() / $window);
$count = $redis->incr($key);
if ($count === 1) $redis->expire($key, $window + 1);
return $count <= $limit;
```
* фиксированное окно даёт «двойной лимит на границе» → для строгого нужен скользящий (zset) или token bucket на Lua;
* счётчики Redis — защита, не отчётность. Деньги в счётчиках не живут;
* `INCR` + `EXPIRE` двумя командами = гонка → Lua или `SET` с TTL.

## Проблемы и решения

| Проблема | Что происходит | Решение |
|---|---|---|
| Cache stampede | ключ протух, все идут в БД | single-flight лок, «мягкий TTL» (отдаём старое, один обновляет) |
| Thundering herd | пустой кэш после деплоя | прогрев + ограничение конкурентности |
| Hot key | один ключ на все запросы | локальный кэш (APCu) на секунды, репликация ключа с суффиксом |
| Кэшируем ошибку/null | «всё сломано» | не кэшировать ошибки; негативный кэш с явным TTL |
| Кэш отстал от БД | разные цифры в UI и в БД | версия в ключе + инвалидация по событию |
| Eviction вытеснил нужное | лимиты/локи пропали | **разделять инстансы**: кэш отдельно от локов/счётчиков |

## Эксплуатация

```bash
redis-cli INFO memory                 # used_memory, maxmemory, maxmemory_policy
redis-cli INFO stats                  # keyspace_hits/misses → hit rate
redis-cli INFO replication            # отставание реплик
redis-cli INFO persistence            # rdb_last_save_time, aof_last_bgrewrite_status
redis-cli --bigkeys                   # большие ключи (плохо)
redis-cli --hotkeys                   # при LFU-статистике
redis-cli --latency-history           # всплески (Redis однопоточный!)
redis-cli SLOWLOG GET 20
redis-cli MEMORY USAGE key
redis-cli CONFIG GET maxmemory-policy  # noeviction|allkeys-lru|volatile-lru
```

## Фразы для собеседования

```
• «Memcached — KV-кэш, Redis — структуры + атомарность + TTL. Выбираю по задаче.»
• «По кэшу нельзя принимать решение о деньгах: показать баланс можно, считать — нет.»
• «SET NX PX, а не SETNX + EXPIRE: иначе процесс между командами даёт вечный лок.»
• «Освобождаю лок только своим токеном, через Lua — иначе сниму чужой.»
• «Если Redis упадёт, система должна стать медленнее, а не потерять деньги.»
• «KEYS * — авария. Только SCAN. А лучше версия в имени ключа.»
• «Кэш справочников и лок/счётчики — разные инстансы: вытеснение кэша не должно ломать лимиты.»
```
