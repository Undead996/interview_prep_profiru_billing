# Словарь биллинга: 70+ терминов, которые надо уверенно произносить

> Формат: **термин** — что это, и одна строка «зачем это помнить».
> Если термин из твоего опыта — сразу держи пример из практики.

---

## A. Участники и платёжный процесс

| Термин | Значение / зачем помнить |
|---|---|
| **Плательщик** | тот, с кого списывают (специалист; в новой модели — клиент). Определяет оферту, чеки, НДС |
| **Мерчант** | получатель денег (мы как продавец услуг) |
| **Эквайер** | банк/PSP, обслуживающий приём денег; отвечает за зачисление |
| **PSP** | платёжный сервис-провайдер: и шлюз, и часто эквайер |
| **Эмитент** | банк, выпустивший карту. **Он решает** по авторизации; большинство отказов — от него |
| **Платёжная система** | Visa/MC/НСПК: правила, клиринг, споры |
| **Процессинг** | техническое ядро: маршрутизация, статусы, сверка |
| **Расчётный счёт** | наш банковский счёт, куда реально приходят деньги |
| **Реквизиты мерчанта** | идентификатор нас у провайдера |

## B. Операции и статусы

| Термин | Значение |
|---|---|
| **Авторизация (auth)** | проверка и блокировка суммы; деньги **не** списаны |
| **Холд / блокировка** | зарезервированная сумма (не деньги, а обязательство) со сроком |
| **Capture (списание)** | превращение авторизации в фактическое списание |
| **Одностадийная схема** | auth + capture одним запросом |
| **Двухстадийная схема** | auth, затем отдельный capture (или release) |
| **Void / Release** | снятие холда без списания |
| **Вебхук / callback** | уведомление о событии от внешней системы. **Не гарантирован и не упорядочен** |
| **Опрос статуса (getStatus)** | независимая проверка факта. Основа догадки и сверки |
| **Идемпотентный ключ** | ключ, по которому повтор не создаёт второй эффект |
| **at-least-once** | доставка «минимум один раз» → консьюмер обязан быть идемпотентным |
| **Dual write** | запись в две системы без общей транзакции — источник рассинхрона |
| **`unknown` статус** | «мы не знаем результат» (отличать от `failed`!) |
| **3-D Secure** | подтверждение плательщика банком (2-й фактор) |
| **Approval rate** | доля одобренных операций; метрика здоровья интеграции |

## C. Возвраты и споры

| Термин | Значение |
|---|---|
| **Возврат (refund)** | обратная операция; отдельная сущность со своим состоянием |
| **Частичный возврат** | возврат части суммы; требует предмета расчёта для чека |
| **Пере-возврат** | возвращено больше, чем оплачено — нарушенный инвариант |
| **Chargeback** | принудительное списание по инициативе держателя; срок на ответ! |
| **Спор / претензия** | процесс разбора с ПС/клиентом |
| **Representment** | наш ответ на chargeback с доказательствами |
| **Компенсация** | новая операция, семантически отменяющая предыдущую (не откат!) |

## D. Учёт и деньги

| Термин | Значение |
|---|---|
| **Леджер (ledger)** | журнал проводок: учёт денег |
| **Проводка** | запись вида «дебет счёта A, кредит счёта B»; **append-only** |
| **Двойная запись** | сумма проводок по операции = 0; деньги не появляются из воздуха |
| **Счёт (account)** | лицевой счёт: пользователя, системный (транзит, выручка, НДС, авансы, обязательства) |
| **Сальдо / баланс** | сумма проводок по счёту; поле в БД — денормализованный кэш |
| **Транзитный счёт** | деньги в пути: у ПС списаны, но на расчётный счёт ещё не пришли |
| **Аванс / предоплата** | деньги получены, услуга не оказана → обязательство |
| **Зачёт аванса** | момент оказания услуги: аванс «закрыт», появляется выручка |
| **Обязательство** | сколько мы должны (перед клиентом или перед специалистом) |
| **Начисление** | возникновение обязательства/выручки |
| **Закрытый период** | отчётный период сдан; изменения — только отдельным документом |
| **Операционный день** | бизнес-день по правилам учёта (не UTC-дата!) |
| **Оборот** | сумма операций за период |
| **Сверка (reconciliation)** | сопоставление наших данных с внешними и с самими собой |
| **Расхождение (discrepancy)** | несоответствие; рутинный предмет разбора |
| **Реестр** | список операций от ПС/ОФД/банка или выгрузка для бухгалтерии |
| **Ас-оф (as-of)** | «на дату/время»: отчёт, воспроизводимый на момент |

## E. Чеки и налоги (54-ФЗ)

| Термин | Значение |
|---|---|
| **ККТ** | контрольно-кассовая техника (обычно облачная, у провайдера) |
| **ФН** | фискальный накопитель: защищённый модуль с подписью |
| **ОФД** | оператор фискальных данных: получает чеки и передаёт в ФНС |
| **ФНС** | налоговая служба (конечный получатель данных) |
| **ФД** | номер фискального документа |
| **ФПД / ФПС** | фискальный признак документа / сообщения — доказательство выпуска |
| **Смена** | рабочий день ККТ; должен открываться/закрываться |
| **Признак расчёта** | приход / возврат прихода / расход / возврат расхода |
| **Признак способа расчёта** | предоплата, аванс, полный расчёт, зачёт аванса, кредит |
| **Предмет расчёта** | что именно продано (услуга/работа/товар + наименование) |
| **Признак агента** | мы выступаем агентом; в чеке есть данные поставщика |
| **ФФД** | формат фискальных документов (версия определяет состав тегов; номера тегов надо сверять) |
| **Чек коррекции** | документ «чек должен был быть, но не был / был с ошибкой» |
| **Чек на аванс / на зачёт** | два документа при расчёте с предоплатой |
| **СНО** | система налогообложения (ОСНО, УСН и др.) |
| **НДС** | налог на добавленную стоимость; ставка и сумма фиксируются на дату операции |
| **Юрлицо / ИНН** | кто получатель выручки и от кого фискализируем |
| **Маркировка** | прослеживаемость товаров (для услуг обычно не применимо) |

## F. Надёжность и эксплуатация

| Термин | Значение |
|---|---|
| **Idempotency (идемпотентность)** | повтор не меняет результат |
| **Outbox** | таблица для событий, пишется в одной транзакции с данными |
| **DLQ** | очередь «мёртвых» сообщений: разбор и алерт, а не свалка |
| **Retry с backoff** | повтор с увеличивающейся задержкой + **джиттер** |
| **Circuit breaker** | «разомкнулся»: не долбить упавший сервис, экономить свои ресурсы |
| **Bulkhead** | изоляция ресурсов: медленный сосед не тормозит деньги |
| **Деградация** | осознанное отключение некритичного (аналитика) ради критичного (приём денег) |
| **SKIP LOCKED** | выбрать только свободные строки: воркеры не мешают друг другу |
| **Deadlock (дедлок)** | цикл ожидания локов; InnoDB откатывает жертву → **нужен retry** |
| **Gap lock** | лок промежутка (в RR) — блокирует вставки, причина дедлоков |
| **MVCC** | версионность строк: обычное чтение не блокирует |
| **Runbook** | «что делать» при инциденте: проверить → действия → кого звать → что записать |
| **Постмортем** | разбор инцидента без обвинений, с конкретными действиями |
| **SLO** | целевой уровень сервиса; на нём строятся алерты |
| **Инвариант** | утверждение, которое обязано быть истинным (сумма проводок = 0) |

## G. Регуляторное и платежное окружение

| Термин | Значение |
|---|---|
| **PCI DSS** | стандарт защиты карточных данных; наша цель — минимизировать scope (токены, редиректы) |
| **Токенизация** | замена карточных данных на токен |
| **СБП** | Система быстрых платежей: асинхронная, результат приходит не сразу |
| **НСПК** | оператор СБП и платёжной системы «МИР» |
| **AML / KYC** | противодействие отмыванию / проверка клиента |
| **Оферта** | условия, по которым мы принимаем деньги |
| **Эскроу** | схема, где мы держим деньги до выполнения условий |
| **Судьба средств** | кому принадлежат деньги в каждый момент (нам или партнёру) |

## Как пользоваться словарём

1. Пробеги и **отметь 15 терминов**, в которых не уверен — выучи их до состояния
   «могу дать определение и пример из опыта».
2. На собеседовании сознательно произноси 5–7 доменных терминов в **правильном контексте**
   (`аванс`, `зачёт`, `проводка`, `сальдо`, `транзитный счёт`, `реконсиляция`, `расхождение`).
   Это моментально меняет восприятие: с тобой начинают говорить как с коллегой.
3. Термины из блока E произноси **с оговоркой**: «состав тегов надо сверить с актуальной
   версией ФФД у вашего ОФД» — так ты показываешь и знание, и корректность.
